# План перевода Mathua

> Создан: 2026-10-22
> Исходный язык: английский. Целевой язык: русский (предположение, подтвердить).
> Upstream: https://github.com/chuma-beep/mathua (коммит `88672fef`)

## 2. Решения, которые нужно принять до начала

1. **Заменить английский или добавить второй язык.** Рекомендую добавить `ru` рядом с `en`, английский оставить языком по умолчанию. Тогда ~20 Go-тестов, которые проверяют английский текст, продолжат проходить, а изменения из upstream будет проще подтягивать. Ещё это даёт шанс отправить i18n в upstream PR-ом.
2. **Как ученик выбирает язык.** Предлагаю переключатель в `/settings`. Выбор сохраняется в профиле пользователя или в `localStorage` для гостя (`mathua_guest_id`). На API язык уходит заголовком `Accept-Language` или параметром `?lang=`. URL-префиксы `/ru/...` при `output: 'export'` удвоили бы статическую сборку, поэтому без них.
3. **Лицензия Algebrica (CC BY-NC 4.0).** Перевод считается адаптацией. Он разрешён с атрибуцией и только некоммерчески, пометку «переведено» нужно добавить в `THIRD_PARTY_NOTICES.md`. Если проект коммерческий, `algebrica/` не переводить и не использовать.
4. **Глоссарий терминов.** Его надо зафиксировать до массового перевода: числитель, знаменатель, смешанная дробь, «mastery» → «освоение», XP, лиги Bronze→Diamond и т.д. Без глоссария 1 млн слов получится несогласованным.

## 3. Архитектура

### 3.1 Веб (UI)
- Свой лёгкий слой: `lib/i18n.ts` с `useT()`, словари `messages/en.json` и `messages/ru.json`. Для `next-intl` без `[locale]`-сегмента при статическом экспорте мало пользы.
- Склонения через `Intl.PluralRules` («1 концепт / 3 концепта / 5 концептов»).
- Числа и даты через `Intl.NumberFormat` / `DateTimeFormat`, у русского десятичная запятая. **Осторожно:** ввод ответов через MathLive и грейдер ждут точку. Форматировать только отображаемые числа, а не ответы.
- Скрипт `scripts/i18n-check.mjs` для CI: ищет отсутствующие и лишние ключи и строки в JSX без `t()`.
- `build-graph.mjs` собирает `concepts.graph.json` с подписями, поэтому нужен вариант на каждый язык (`concepts.graph.ru.json`).

### 3.2 Данные (концепты, курсы, уроки)
- Оверлей вместо правки оригиналов: `data/i18n/ru/concepts.json` (`id → label`), `data/i18n/ru/courses.json`, `data/lessons/kp/ru/*.json`, `data/lessons/teaching/ru/*.md` и т.д.
- Загрузчик в `internal/lessons` и `internal/concepts` ищет файл для локали, а если его нет, берёт английский. Так перевод можно выкатывать по частям.

### 3.3 Генераторы задач (главная работа)
- `Generate(ctx GeneratorContext)` уже получает контекст: добавить в него `Locale`.
- Вынести шаблоны в каталог: `internal/i18n` поверх `golang.org/x/text/message` (там есть plural/select). Ключи вида `frac.sub.whole.question` и аргументы.
- Русский требует согласования: «%d метр/метра/метров», род у предметов в текстовых задачах. Для таких шаблонов использовать plural-селекторы, а не просто `Sprintf`.
- **Ответы словами:** сравнивать по каноническому id (`yes`, `parabola`), а для каждой локали держать список синонимов («да», «парабола»). Варианты `Choices` проверять по id варианта, а не по отображаемому тексту. Это затрагивает `internal/grader/choice.go` и фразовую логику из последних коммитов.
- В истории (`/history`) хранится уже сгенерированный текст. Старые попытки останутся на том языке, на котором их решали. Это приемлемо, менять схему БД не нужно.
- Существующие тесты (`solutions_contract_test.go`, `pools_test.go` и др.) прогонять в обеих локалях. Добавить тест: каждый ключ есть в `ru`, и в каждом шаблоне одинаковые `%`-аргументы.

### 3.4 Сервер и грейдер
- Тексты `Feedback` (`"Incorrect choice"`, `"Could not parse numeric values"`) заменить на коды, а текст подставлять на клиенте через словарь.
- `internal/ai`: в системный промпт добавить «отвечай на языке: {locale}».

## 4. Процесс перевода контента (~1,2 млн слов)

1. Машинный перевод через LLM пачками по файлу. В промпт входит глоссарий. LaTeX (`\(...\)`, `$$...$$`, `\frac` и т.п.), код, ссылки и пути к картинкам переводить запрещено.
2. Автоматическая валидация каждого файла:
   - формулы совпадают с оригиналом токен в токен;
   - KaTeX рендерит формулы без ошибок (можно взять за основу `cmd/latexdump` / `cmd/latexfix`);
   - заголовки и markdown-структура совпадают по количеству;
   - ссылки на диаграммы целы.
3. Ручная вычитка по приоритету курсов: сначала школьная программа (arithmetic, fractions, prealgebra, algebra, geometry), потом вузовская.
4. Объём: примерно 1,5–2 млн входных и 2,5–3 млн выходных токенов на один проход. Стоимость в первую очередь зависит от выбранной модели, а не от объёма.

## 5. Этапы

| Этап | Содержание | Оценка |
|---|---|---|
| 0 | Решения из §2, глоссарий, ветка `i18n` | XS |
| 1 | Инфраструктура: `Locale` в контексте/API, загрузчики с fallback, `useT()`, переключатель в настройках, CI-проверка ключей | M |
| 2 | UI: вынести все строки, перевести, учесть склонения и форматирование чисел | M |
| 3 | Названия концептов, доменов, курсов, KP-структура (1250 файлов), граф по локалям | S |
| 4 | Генераторы: каталог и рефакторинг 32 пакетов, начать со школьных доменов; синонимы ответов; коды фидбэка | XL |
| 5 | Тексты уроков: машинный перевод, валидация, вычитка школьных курсов | L (+ вычитка) |
| 6 | Диаграммы: локальные перегенерировать с русскими подписями, Algebrica оставить или перерисовать | S–M |
| 7 | Прогнать Playwright e2e в `ru`, проверить на мобильных (`docs/mobile-device-checklist.md`) | S |
| 8 | Документация и README (по желанию) | M |

**MVP:** этапы 1–3, плюс этапы 4–5 только для курсов до 8-го класса. После этого можно полностью пройти школьный трек на русском.

## 6. Риски

- **Регрессии грейдера.** Ответ словами или вариант выбора на русском может перестать засчитываться. Нужны тесты на каждый такой генератор.
- **Расхождение с upstream.** Репозиторий активно меняется, каждое изменение генератора придётся заново оборачивать в ключи. Лучше договориться с автором об i18n в upstream.
- **Сломанный LaTeX после машинного перевода.** Защищает только автоматическая валидация из §4.
- **Длина строк.** Русский текст примерно на 15–30% длиннее, кнопки и мобильная вёрстка могут поехать.
