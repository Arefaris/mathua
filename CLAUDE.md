# CLAUDE.md — форк Mathua с русским переводом

Это форк https://github.com/chuma-beep/mathua. Правила оригинального проекта лежат в
[AGENTS.md](AGENTS.md) и действуют полностью. Ниже правила, которые есть только в форке.

## 1. Регулярно подтягивайте изменения upstream

Upstream меняется очень быстро: за первые сутки после клонирования в нём появился 71 коммит.
Чем дольше форк не синхронизирован, тем больше конфликтов в обёрнутых в `t()` компонентах. Кроме
того, автору тем труднее забрать нашу работу к себе.

**Когда:**
- перед началом любой новой задачи или раунда перевода;
- не реже раза в неделю, даже если работы нет.

**Remotes:**
- `upstream` — оригинал `chuma-beep/mathua`, push в него отключён (`DISABLED`);
- `origin` — наш форк. Пока форка на GitHub нет, `origin` указывает на оригинал, и push в него тоже
  отключён. Когда форк появится: `git remote set-url origin <url форка>` и
  `git remote set-url --push origin <url форка>`.

**Порядок:**
1. `git fetch upstream`
2. `main` — точная копия upstream, своих коммитов в нём не бывает:
   `git switch main && git merge --ff-only upstream/main`
3. Влейте `main` в рабочую ветку (`i18n-ru`): `git switch i18n-ru && git merge main`.
   Делайте именно **merge, а не rebase**: ветка публикуется в форке, и переписывать её историю нельзя.
4. Разрешите конфликты и доведите перевод до upstream:
   - новые и изменённые строки интерфейса оберните в `t()` и добавьте в словари `en` и `ru`;
   - новые темы: метки в `data/i18n/ru/concepts.json`;
   - новые шаги уроков школьных разделов: файлы в `data/lessons/kp/ru/`;
   - новые курсы: `data/i18n/ru/courses.json`;
   - новые карточки рекомендаций: `internal/server/localize.go`.
   Пропуски ловят проверки оверлеев и `npm run i18n:check`.
5. Прогоните проверки: `go vet ./...`, `go test ./...`, а в `web/next-app` —
   `npm run typecheck`, `npm test`, `npm run lint`, `npm run build`. Тесты, которые падали
   ещё до синхронизации, сверяйте с `main`, а не чините молча.
6. Закоммитьте merge. Если форк уже есть, запушьте `main` и `i18n-ru` в `origin`.

## 2. Не мешайте будущему слиянию с upstream

- Работа форка ведётся в ветках (`i18n-ru` и производных), `main` не трогается.
- Не переформатируйте чужой код и не делайте попутных рефакторингов: каждое лишнее изменение — это
  будущий конфликт.
- Коммиты тематические, в стиле upstream (`feat(i18n): …`, `fix(server): …`), чтобы автор мог
  забрать любой из них отдельно.
- Переводы лежат в отдельных файлах-оверлеях. Английские оригиналы не редактируются.
- Push в upstream запрещён.
