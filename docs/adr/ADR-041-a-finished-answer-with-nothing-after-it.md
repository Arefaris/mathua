# ADR-041: A finished answer with nothing after it is a bug, and it was not the learner's fault

*2026-10-05*

the report was a `/learn` transcript ending at a verdict with **no instruction on what to do next**. Three defects, found by reading the transcript rather than the code. **(1) The feed dead-ended silently.** `geo.basic.points_lines`'s generator has exactly **four** distinct question texts (`internal/generator/geometry/generators.go:45`, a fixed `items`/`descs` table). The learner answered all four; `exclude` then emptied the candidate set; `/api/lessons/{id}/practice` answered **200 with `questions: []`**; and `LearnStepper`'s three `if (!nq) return` sites turned that into no card, no message and no way forward. Fixed at both ends: the endpoint falls back to repeats rather than returning empty (and answers 503 if the generator genuinely produces nothing, which is a different failure and must not look like success), and the client routes exhaustion through the same `advanceSection` the 2-in-a-row rule uses, so "this section is over" ends somewhere the learner can move from, with a note saying why. **(2) Nothing could see it, so I measured it.** `TestEasyPoolsDiscriminate` checks that *answers* discriminate, which a four-question generator passes with four answers; question *texts* were never counted anywhere. `internal/generator/all/bank_test.go` now samples every one of the 657 generators the corpus then held at four difficulties and counts distinct question texts: **378 of 657 (58%) sit under a 12-question variety reference**, and **3 cannot fill a single 3-question request** — `calc.integral.{power_rule,substitution,ftc}`, whose `scale := int(1 + ctx.Difficulty*5)` leaves the integer range 2 wide at difficulty 0.3. The gate is deliberately set at *can fill one request* and the variety share is only reported, because a threshold above the corpus median would be a content backlog wearing a test's clothes; the three are allowlisted with reasons so the set cannot grow silently. Getting there required extracting `generator/all.Register`, since `cmd/mathua` wired the seventeen domains inline and a diagnostic built from its own list would drift from production the first time a domain was added. **(3) The header mixed two scopes.** `1/2 correct` reset on every knowledge-point advance while `+3 XP` summed every card in the feed, so a learner three questions in with two correct saw two different spans on one line and the count was the one that read as wrong — the scope mismatch ADR-040 deferred. The tally is now two per-concept counters, which also removes an array that grew for the whole session to serve a `.length`. **One honest wrinkle in the measurement:** the counts are *lower bounds*, not exact banks, because generators draw from the global `math/rand`, which Go 1.24+ auto-seeds and `rand.Seed` can no longer override — two runs differed in the high digits until that was accepted rather than papered over. Sampling can only miss variants, never invent them, so a sample never over-reports, which is the direction a gate needs. Also fixed en route, found by the full suite rather than by reading: `enterAnswer`'s tap path initially relied on MathLive's 300ms focusin timer to raise the keypad, and slipped under a loaded parallel run — one flake traded for another — so it now calls `showVirtualKeyboard`, which shows the panel directly. Two consecutive full E2E runs at 218 passed, 0 failed.
