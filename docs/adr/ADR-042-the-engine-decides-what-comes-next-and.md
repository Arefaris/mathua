# ADR-042: The engine decides what comes next, and the browser is told

*2026-10-06*

**amends ADR-018 and ADR-023, which had left a second scheduler in the browser.** Those ADRs moved the *selection* to the server and kept the ranking on the client, on the reasoning that the shelf was presentation. It was not: `lib/nextUp.ts` recomputed prerequisite closure (`prereqMet`), status buckets (`countsAsMastered`), due-review counts, XP estimates (`effortBase`, `xpFor`, a copy of `internal/xp`), and a weighted ordering (`fixedWeightPolicy`). So `internal/scheduler` chose *which* concept to serve a question from while the browser chose *what to recommend*, from the same inputs through a second implementation of the same rules, and `PositionBlock` and `NextUpSummary` could each render a different answer from the same fetch. That is ADR-040's failure mode one layer up: a model with no authority, kept because it read like authority. `internal/scheduler.Recommend` now takes the learner state the engine already holds and returns `{primary, alternatives, generatedAt}` with `badge`, `detail` and `cta` **chosen server-side**, over `GET /api/next`; `lib/nextUp.ts` loses `buildCandidates`, `selectShelfHead`, `selectShelf`, `selectNextUp`, `effortBase` and `xpFor`, and `test/shelfHead.test.ts`/`nextUp.test.ts` are deleted rather than left passing. Five client fetches (`getActivity`, `getProgress`, `getWeaknesses`, `getDueReviews`, `getScores`) collapse to one on `/learn`, `/profile` and the Learn done card. **Three bugs were the migration's, not its subject's, and all three are recorded because each is a shape someone else would have re-created.** (1) `/profile` **crashed on every load**: `head` is null until the fetch resolves and the "recently unlocked" memo dereferenced it. That memo had run against a synchronously computed head, so moving the decision is precisely what made it null first. (2) Swallowing the network error in each caller **dead-ended the Learn done card**, it always held a shelf, so its existing failure branch ("Back to Profile", and the guarantee that no link points back at the concept just finished) became unreachable. The absorption belongs in `getNext`, which is where the five replaced calls each used to do it. (3) `recommendationResToShelf` assumed `alternatives` was present, and it is exported, so one absent field took out the home page. **One test was tied to a shape rather than an invariant** and is worth naming because the shape was going to change again: the fail-soft test wanted "a Continue link"; the library fallback's `/study` href carries no concept id, so `canContinue` is false and the card correctly shows its failure branch. It now asserts the invariant, a way forward, and never a link back at the finished concept. `test/masteryAuthority.test.ts` grew the structural guard this needs: `lib/nextUp.ts` computes no ranking, no surface ranks for itself. **Closed after review, and it was a missing task rather than a wrong number.** `ReviewsDue` counted a row only when its *stored* status was not `MASTERED`, precisely the population `scheduler.effectiveState` explicitly puts in the review bucket (`snap.Status == StatusMastered && NextReviewDue due → isReview = true`). So the count and the candidates disagreed, and since `selectTasks` takes the review bucket only when `DueReviews > 0`, a learner whose sole due review was a decayed-mastered concept was recommended nothing to review while `NextReviewQuestion` would have served one. The guard's own comment described the behavior the code did not have. Two neighbours went with it: `ConceptsMastered` counted every non-UNSEEN row, so a concept the learner had merely *started* counted as mastered, harmless today only because `AttemptedDays` already guarded the sole consumer, and fixed because a field named after a fact it does not report passes the discrepancy to the next caller rather than the comment; and an exported `Recommendation.Generated bool`, set once and read nowhere, which had no `json` tag and so shipped as `"Generated":true` in the payload. The new test pins the first and says in its own comment that it does not pin the second.
