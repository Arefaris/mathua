# ADR-032: Verified 0.111.0 configuration, and one doc that would have shipped broken

*2026-10-03*

MathLive defaults `_soundsDirectory` to `'./sounds'` and `keypressSound` to `keypress-standard.wav`, loaded with a `fetch()` on **every keystroke**. Mathua ships `public/fonts` and never shipped `public/sounds`, so each key requested a file that does not exist — measured as two taps producing two requests for `/…/chunks/sounds/keypress-standard.wav`. Fixed with `MathfieldElement.soundsDirectory = null` and `keypressVibration = false`; the statics are required because the *instance* accessors throw `Error("Use MathfieldElement.soundsDirectory instead")`. Second finding, and the reason "verify the API, trust the docs" is now a gate rather than advice: **0.111.0's docs say `geometrychange` carries `evt.detail.boundingRect`, and it does not** — the library dispatches a plain `new Event('geometrychange')` with no detail, from a ResizeObserver and from `stateChanged()`. A handler written to the documented shape reads `undefined`, computes height 0, and reports the keypad closed forever, which is precisely the failure it exists to prevent. The rect is `kb.boundingRect`. MathLive positions its own panel against the field, so it does not cover the editor; what it cannot do is shrink the page, so the height is republished as `--mathua-keyboard-height` plus `data-mathua-keyboard` on `:root` for stylesheets, rather than a hardcoded pixel value. `mathVirtualKeyboardPolicy` is left at its verified default (`'auto'`) rather than set redundantly, and `fontsDirectory` likewise, since `'./fonts/'` is already correct for the 300 kB of webfonts Mathua copies at build time. First Load JS across ten routes: **3603 → 3605 kB gzip total (+2)**; MathLive 215 kB and Compute Engine 787 kB both stay out of initial JS. B2 of the addendum verified clean: `math-field { font-size: 1rem }` with no `html` override computes to 16px, clear of the iOS focus-zoom threshold — the 15px rule is `body`-only. Safe-area already handled in `ChromeToggle`/`ConceptGraphFlow`/`/history` and deliberately not added to the answer area, since MathLive's panel already clears the home indicator and double-padding would push the field away from the keypad.
