# ADR-027: The self-check is a simplification, not an equivalence check

*2026-10-03*

the request was "tell the learner whether this looks equivalent to the answer". The client does not hold the expected answer, and shipping it to power a hint would make the hint an answer oracle and undo ADR-005, so `components/math/SelfCheck.tsx` shows only what the learner's **own** expression simplifies to (`1/2+1/3` → `5/6`, `\sqrt{x^2}` → `|x|`). **Reframed 2026-10-03 at the owner's direction** — the addendum's Section E specified a three-valued `true|false|undefined` with `undefined` rendering no feedback. The shape was already satisfied under different names (`equivalent|different|unknown`); what differed was the correctness-feedback framing, which is not implemented and is not planned. The contract is now stated in `equivalence.ts` and `docs/math-input.md`, and `test/selfCheck.test.tsx` asserts that **no** state renders a verdict, using a real pair for each — `x²+2x+1` vs `(x+1)²` is `equivalent`, `2^10` vs `1024` is `different`, `\sqrt{x²}` vs `x` is `unknown`. Note `2x+3` vs `x²+2x+1` is `unknown`, not `different`: CE declines rather than guess, which is what makes `unknown` load-bearing. Measured while building it: `isEqual` returns `undefined` for the symbolic identities that matter (expanded vs factored, every trig identity), `isIdenticallyEqual` is the only call that can *refuse* — correctly declining `\sqrt{x^2}` vs `x` — but also declines to call `2x+3` and `2x+4` different, so a hint built on it must be able to say "I don't know"; `simplify` is the tie-breaker and is what makes trig work. Compute Engine is **788 kB gzip** (4× MathLive), so it is dynamically imported (+1 kB on routes with the editor, +0 elsewhere, never in initial JS) and skipped entirely when `navigator.connection.saveData` is set or the type is 2g — a one-line hint is not worth someone's data allowance. Rendering it is not the main difficulty; the arithmetic guard is: CE parses prose as a product of letter-variables and calls it valid, so only input containing an operator/digit/power/radical is ever sent. Two incidental findings recorded in `docs/math-input.md`: importing CE silently switches on MathLive's MathJSON paste (CE registers `globalThis[Symbol.for("io.cortexjs.compute-engine")]`, asserted in `test/equivalence.test.ts`), and CE 0.147's real MathJSON differs from its documentation — `Sqrt` survives canonicalisation and `x^2` stays `Power`, so a Go grader written to the docs would fail on most inputs. Also fixed en route: `MathLiveField`'s `emit` was a `useCallback` over `onChange`, so a host passing a fresh arrow every render re-ran the effect that pushes the host's value in, wiping what the learner had just typed; `emit` is stable via a ref and the effect keys on `value` alone. Reverting is one file (`SelfCheck.tsx`); nothing else in `components/math/` imports it.
