# ADR-024: Progress moved off the hub (2026-10-01), **partly superseded by ADR-025**

Progress moved off the hub (2026-10-01), **partly superseded by ADR-025**: `/profile` was 586 lines doing five jobs, identity, a settings row, the task queue, activity, weaknesses, efficacy and per-domain mastery, which contradicted ADR-001 (`Profile=hub`) and ADR-023 (a compact summary). The report moved to `/progress`, ordered by the questions a learner asks: `PositionBlock` (mastered · unlocked · in progress · locked, plus the frontier the scheduler would serve next) → by domain → how you're doing → activity → struggles → recently unlocked. The hub keeps identity, the one Next task, the alerts and the new-user block, and links onward; it no longer fetches activity-adjacent report data beyond what `selectNextUp`/`selectShelfHead` need. Mastery counting is centralised in `lib/progress.ts` (`isMastered`, `prereqMet`, `countByDomain`, `countOverall`) after four copies had accumulated, and the report is deliberately not a percentage-of-657, mastered-against-unlocked is the pair a learner can act on. `Engine.GetProgress` now applies `mastery.EffectiveStatus` on read so a decayed concept is `DECAYING` everywhere and not just to the scheduler; `prereqMet` accepts `DECAYING`, matching `scheduler.prereqsMet`, so decay never relocks successors. `/progress-card` renamed `/history` (`AttemptList`), because the sidebar's "Progress" entry pointed at a mistake log, the label was the bug. Cohort analytics stay on `/docs/efficacy`, never on a learner's own report. Deferred: persisting the diagnostic placement so `FrontierLabel` survives the session, and an explicit exit for the `/session` + `/concept` stubs.
