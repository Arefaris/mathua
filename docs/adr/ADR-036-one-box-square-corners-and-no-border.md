# ADR-036: One box, square corners, and no border outside the palette (2026-10-04) — three independent commits, because the report bundled three unrelated defects

One box, square corners, and no border outside the palette (2026-10-04) — three independent commits, because the report bundled three unrelated defects: "the input boxes seem to have two active border states", "the boxes have rounded borders they should be square", and "all borders in all states in sync with the main colors". **(1) Two boxes, one token.** `statusClasses` put `border border-mathua-border bg-mathua-code px-3 py-2 focus-within:border-mathua-blue` on the wrapper div while `<math-field>` declared its own `border: 1px solid var(--border)` and turned blue on `:focus-within`; both transitioned over 0.15s, so focusing lit both at once, 24px apart. It read as two *states* because it is one token painted twice — `mathua-blue` **is** `var(--accent-blue)` — so there was no second color to reconcile, only a second box. The wrapper was also the wrong element to own a border: it wraps `SelfCheck` too, so the outer box grew downward to enclose the hint once anything was typed, and the verdict colors landed *outside* the field's opaque background, so `correct` drew a ring around a still-grey box. **The box belongs to the control; the wrapper is layout-only.** Two consequences: the field's `min-height` goes 2.75rem→3rem because the 48px floor came from the wrapper's `min-h-12` and `e2e/mobile.spec.ts` asserts the *field* is ≥48px; and its padding goes `0.5rem 0.75rem`→`0.5rem 1rem` to match `Input`'s `px-4`, because the wrapper stacked `px-3 py-2` on top, so the field reflowed when the plain input stood in while the chunk loaded (ADR-031 already made those two share a placeholder for this reason; the inset was the remaining tell). The verdict now rides on the field's own border as **`data-status`, not a utility class** — `math-field.mathua-math-field` outranks any Tailwind class, so `border-mathua-green` on the element loses to the `border-color` declared there and would not render at all. **(2) Rounded corners were documented and unenforced.** `app/docs/contributing` says "no rounded corners" and `components/ui/button.tsx` says "No rounded-*", yet `ConceptGraphFlow.tsx` was the only file in the app that used neither, and contradicted *itself*: one button already said `rounded-none`. Eight bordered boxes there plus the `ProgressSummary` stat tiles — which are on `/graph` too, since `app/graph/page.tsx` renders that component, which is why "the graph page" covered both reports. Coupled find: the mastered/learning glows are `::after` at `inset: -3px` with `border-radius: 5px`, so squaring the card leaves them visibly wrong at the corners — the same class of bug as the keycap that typed its own name, the thing you change is never the only thing that depended on it. Rounded is now **allowed only where there is no border**, which exempts dots, avatars, `ProgressBar`, switch knobs and `MasteryBadge` by rule rather than by an offender list that goes stale. **(3) Borders were outside the palette, and the guard had allowlisted them.** Eleven verdict borders were raw Tailwind values; `test/themeTokens.test.ts` documented the allowlist because "default-palette modifiers emit normally" — true, and beside the point: nothing could reach them, so a correct border was a *different green* from `--accent-green` and the two diverged further in dark. `green-faint`/`red-faint` join `blue-faint` as `color-mix` tokens, re-verified against emitted CSS rather than trusted from the config comment: `border-mathua-green/40` produces **no rule at all**, so the tempting edit `border-green-500/40`→`border-mathua-green/40` looks like it worked and leaves the border uncolored. Both are 40%, collapsing /30 and /50 onto one weight. One judgement call: the reviews-due alert was the app's only yellow, and there is no amber (`--accent-teal` is hue 250, a second blue), so adding a token would add a hue rather than sync one — it is a prompt with a CTA and every other CTA is the brand blue, so it is now blue. **Deferred:** eight `text-red-400`, six `text-yellow-400`, two `text-green-400` state labels and the `MasteryBadge` warm fills have no token to move to today, and `text-yellow-400` on a light surface is a contrast question of its own. Both square guards were caught **passing vacuously** first — jsdom resolves an inline `borderRadius` but has no stylesheet, so a computed-style-only check reported clean over six of the eight boxes — and both are now asserted against the class list too.
