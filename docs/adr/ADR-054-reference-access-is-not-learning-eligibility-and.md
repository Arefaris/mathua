# ADR-054: Reference access is not learning eligibility, and `/study` is restored as a context-bound reference page

*2026-10-11*

**the reported bug was a dead end made of a mastery check.** `/learn?concept=alg.factor.trinomial` lists its prerequisites `alg.factor.gcf` and `alg.poly.foil`; both are `locked` for a fresh learner, and `PrerequisitePanel.prereqHref` returned `null` for `locked`/`upcoming`, so each rendered as an unclickable "Locked" span. Nothing navigated anywhere, even though the material existed (`data/lessons/kp/alg.factor.gcf.json`, `teaching/alg.factor.gcf.md`) and `/api/lessons/{id}/kp` is not eligibility-gated. **Two deliberate decisions had combined into the fault.** ADR-047 closed `/study` as a learner workflow and moved the reference into `ConceptReference` inside `/learn`, but `LearnStepper` renders that panel only for an *eligible* target — an ineligible one early-returns the prerequisite panel — so a locked concept's material had no route at all. ADR-051 made the practice and answer endpoints enforce `prereqsMet`; that gate is right and stays, but it was read as if it also governed *reading*. **The correction separates the two at the boundary they belong to.** `/study?concept=X` is restored (ADR-047 amended) as a reference and exploration page: it requires a concept, renders that concept's instructional material whether or not it is mastered, and awards nothing; without `?concept=` it forwards to `/learn` rather than presenting an index. It is not a catalogue — no domain index, no lesson list, no search — and it is not in nav or the sitemap; discovery stays the server-state-driven `/domains` picker, and practice stays the eligibility-gated `/learn`. Every prerequisite links to `/study?concept=P`, `locked` and `upcoming` included; the separate *Practise this concept* control enters `/learn?concept=P` through the existing gate, and routes a mastered concept to `/review` (ADR-037). **The return is URL state, not component state**, because navigation unmounts the component that held it: a chain of hops travels as repeated `?return=` paths, most-recent-first, and a back-link pops the top and re-appends the rest, so `learn T -> study P -> study Q -> back -> P -> back -> T` survives a reload. The stack is attacker-reachable, so malformed entries are dropped, and pushing the current page drops any entry naming the same concept, which makes a cycle collapse instead of growing and stops any back-link naming the page you are on (`lib/learnReturn.ts`, `test/learnReturn.test.ts`). **The content audit found less missing than feared, and reported what is.** The 220 `data/lessons/solutions/*.json` schemas are **already surfaced**, not lost — `internal/solutions` interpolates them server-side into every generated question's `Explanation` (`Registry.explain`) — so they are not static reference text and cannot be rendered as one without an instance; they are left where they belong. The 36 `minimal` knowledge points (`internal/lessons.SliceAudit`, 32 concepts, none on a first card) are `/learn`'s bounded teaching slice, an honest placeholder by design, and `/study` shows the full lesson article that already exists alongside them, so the reference does not inherit the placeholder. A concept with no shard and no article shows "Detailed study material is not available for this concept yet" and keeps its prerequisite and practise links, rather than a titled empty panel. `ConceptReference` gained a `page` variant for `/study`; the `/learn` panel is unchanged, collapsed and link-free. **What moved and what was checked.** `PrerequisitePanel` is one list shared by `/learn`, `/domains` and `/study`, and it is now impossible to render a prerequisite without a working link. `test/learningPath.test.ts` was rewritten from "no `/study` anywhere" to the properties that still matter — `/study` is not in nav or the sitemap, has no catalogue, requires a concept, and no surface records reading as progress — and `flows.spec.ts` drives the reference page and the practise hand-off in a browser. **The surfaces read as three different things, on purpose.** `/domains` stays the structured picker; `/study` is a reading column with the DAG neighbourhood — *Depends on* and *Unlocks*, drawn from the server's prerequisites and the corpus's dependents — beside it and one prominent *Practise this concept →* hand-off into the assessed loop; `/learn` keeps its prerequisite panel, retitled **Prerequisites**, with the same openable rows. `Locked` is a state **label**, never a disabled control: a locked or upcoming neighbour is still a link, because the state describes assessed-practice eligibility, not whether the material may be read. A missing-content concept keeps its page, its neighbour links and its practice hand-off, and says the material is not available yet rather than showing a titled empty panel. The locked-topic panel had also dropped the return target, so a prerequisite opened from it could not find its way back — the panel now carries the same return stack as the eligible one. Verification: 730 web unit tests, the Go server suite including `TestLessonKP_LockedTopicIsReadable` (a locked topic's shard answers 200 while its practice stays 403) and `TestReadiness_ListsDAGPrerequisitesAcrossDomains`, `tsc`, and `check_docs.py` / `check_ste.py`.
