# ADR-052: Administration reaches a phone, and the mobile menu was dead while it said otherwise

*2026-10-08*

**the reported gap was one missing link, and tracing it found that every link in the mobile compass menu was in the DOM and unreachable.** The panel hangs off `<header>` rather than off its trigger's wrapper — a deliberate consequence of the collapse clipper (`test/header.test.tsx`) — and the outside-`mousedown` test named only the trigger. A mousedown on one of the panel's own items was therefore "outside", which unmounted the link before its click could activate it: the menu opened, listed Leaderboard, Settings and Login, and did nothing. The profile menu had `menuPanelRef` and the nav panel did not, so one assertion was copied and the other forgotten. The fix is a ref on the panel and both names in the containment test. **What let it ship is the shape of the existing tests:** they asserted the labels and hrefs of items that were in the DOM, which is exactly the state that was broken. The regression is now asserted as behavior — a link must still be attached after the mousedown that precedes its own activation — and driven for real in `e2e/admin.spec.ts`, because a presence assertion cannot see an item that unmounts before it is pressed. **The Admin entry was the symptom.** It has been in the desktop rail since Admin V2, and `/profile` is one tap from the tab bar, so on a phone an administrator had no route to administration at all except typing a URL. It is now in the mobile overflow, appended by `overflowLinks(loggedIn, isStaff)`, which defaults to false so every existing caller keeps the learner menu it had. **A fourth role was the other half of it.** `UserInfo.role` was typed `'student' | 'admin'` while the server has sent four values since ADR-049 (`storage.Role`, `student/moderator/admin/owner`), so a `moderator` or `owner` did not type-check as staff and the type silently narrowed what the app could offer — the same duplicate-schema failure ADR-043 recorded for `UserInfo` itself, arriving through the type rather than a string. It now mirrors `storage.Role`, `isStaffRole` is shared in `lib/auth` (the copy in `/profile` had no way to learn the staff set is moderator-or-above, so the two answers to one question were free to disagree), and the predicate matches the server's `Role.IsStaff()`. Offering it grants nothing: every `/api/admin` route re-reads the role server-side (ADR-048, ADR-049), so this is the invitation the server was always the authority for — stated in the code at the point it is granted. Unchanged: the tab bar stays at five, `/admin` is not a tab, and a learner or a missing `role` sees no Admin entry anywhere. Verification: 672 web unit tests including the three staff roles, and both CI e2e shards (117 + 116, single worker) including two new phone-viewport cases that reach the real page.
