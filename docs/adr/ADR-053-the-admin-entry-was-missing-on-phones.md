# ADR-053: The Admin entry was missing on phones because the login path dropped the role, and no test walked that path

*2026-10-08*

**ADR-052 shipped the link and it still did not appear, because ADR-052 was reading the wrong layer.** Adding `Admin` to the mobile overflow could not work while `mathua_user` held no role, and it held none for two separate reasons. **`establishSession` kept two of the four roles.** `if (me.role === 'admin' || me.role === 'student') merged.role = me.role` had survived Admin V2 verbatim, so a **moderator or owner was dropped at login** — on every device — and the stored session carried no `role`. The narrowing was invisible because `UserInfo.role` was typed `'student' | 'admin'` too: a type, a comparison and a test all agreed with each other and all disagreed with the server, which is ADR-043's duplicate-schema lesson in three places at once. **`mathua_user` is a cache, and a cached privilege is only as fresh as its last write.** The role was written exactly once, at login, and nothing re-read it: a phone signed in before Admin V2 had no role and no path to ever get one, while a desktop that had re-authenticated showed the entry. Same account, two devices, one defect. So the role is now read from the server where it is offered — `fetchMe` repairs the session and broadcasts `auth-changed`, and `useAuthState` calls it once per load **only when the role is missing**, because "the server said not staff" is worth caching and "we could not ask" is not: a failed read returns null rather than caching a role, because caching "not staff" from a blip would reproduce the original bug as a stored answer. `/profile`'s `isAdmin` and the compass menu now see a repaired session. **What let this ship is that every test walked around it.** Each one injected `role` directly into `localStorage`, skipping the login path that loses it, and the viewport was never a phone's: the entry was asserted to work by constructing the state that makes it work. The guards now include `establishSession` against all four roles (including one the server might add later), `fetchMe` against an offline read and a server that sends no role, and two browser cases at a phone viewport that drive the path the device actually takes — one opening the **sidebar sheet**, which is where a phone user looks first and which is mounted only while open (`sidebar.tsx:190`), the other recovering from a stale session the way a real phone has one. Recorded because the failure was not "a link was missing": it was a privilege that the client could never learn, discovered by a person on the device it did not work on.
