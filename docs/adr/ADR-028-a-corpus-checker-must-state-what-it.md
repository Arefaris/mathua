# ADR-028: A corpus checker must state what it did not check

*2026-10-03*

`web/next-app/scripts/normalize-latex.mjs` (`make latex-normalize`) runs all 46,872 math spans in the lesson corpus through Compute Engine, because `test/latexCorpus.test.ts` proves KaTeX can *render* every lesson and KaTeX guesses at malformed input, so it is a weak signal. Four findings, each of which was a bug before it was a rule: spans must come from `cmd/latexdump -spans` (new flag) over the canonicalized body via `latexnorm.Scan`, because a dollar can be a delimiter or a currency amount and a regex reports every "$5 and up" as broken; **`ce.parse` is total and does not throw** — a syntax error returns a tree containing `["Error", reason, …]`, so a try/catch reports a corpus with thousands of broken spans as clean, which is worse than no report because it is a confident lie; **a parse failure is not a defect** — CE is a numeric CAS and this corpus is abstract algebra, topology and group theory, so it declines to type `U \times F` as `incompatible-type: number, function` after parsing it perfectly, and ~1,600 spans fail only because CE lacks a command, so reasons are bucketed `syntax` / `not-numeric` / `ce-gap` and only the first is reported; and **the buckets must reconcile** to the corpus total with an exit-2 on mismatch, because that assertion is what caught two earlier versions reporting "20,549 of 46,872" while reporting success, and the summary states `checked_pct` because a checker that quietly covers 44% of its input is not a clean bill of health. Result after `cmd/latexfix`: 37,657 clean, **228 malformed** (137 unique in 60 files), 8,903 unchecked, 0 engine crashes. `cmd/latexfix` (now 16 tests) took it from 517 by three mechanical classes, each of which was a bug before it was a rule: **an attached apostrophe is a typo but a curly quote is not** (`f’`→`f'`, but `‘a\ \text{is less than}\ b’` must keep its quotes or LaTeX renders primes); **the Algebrica scrape is double-escaped** — it wrote `\\(`, which latexnorm reads as prose, so 14,936 formulas were invisible to every region-based tool and only the canonicalizer (which rewrites them to `$…$`) made them checkable, and un-escaping is provably free because canonicalize emits identical output for both forms; and **removing a `✓` can create a defect**, since `$42✓$`→`$42$` is a bare numeral set as math which the canonicalizer escapes to `\$42\$` and the learner sees literal dollars (ADR-016), so a span that becomes a bare numeral loses its delimiters too. The first version of the fixer wrote `r.Content` over `src[r.Start:r.End]`, stripping the `$…$` off 33 files — `Content` excludes the delimiters — so delimiter preservation, `\text{}` masking and idempotence are now tests. `make validate` excludes the checker and CI runs it `continue-on-error: true`; the remaining 137 unique spans need judgement, not a rule. Reasoning about CE's limits is recorded in `docs/math-input.md` §7.
